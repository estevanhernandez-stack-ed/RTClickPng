## GitHub release body (markdown)

> One menu entry, and your originals stay put.
>
> ### What changed
>
> - **One Right Click to PNG entry, with the app icon, in both menus.** Convert to PNG,
>   Copy as PNG and Settings… now sit in its submenu, in the modern menu and in *Show more
>   options* alike. The classic menu used to scatter them, iconless, between other apps'
>   entries. ([#2](https://github.com/estevanhernandez-stack-ed/RTClickPng/issues/2))
> - **Originals stay untouched in mixed selections.** A `.jpg` selected with other images
>   and sent through *Convert to JPEG* (or a `.png` through *Convert to PNG*) used to be
>   re-saved over itself. Files already in the target format are now skipped, and the
>   engine refuses to write any file onto itself.
> - **The settings app only logs when something goes wrong**, and keeps that log in the
>   app's own folder, so uninstalling removes it. The old per-launch log is deleted on
>   the first run.
> - **Stability:** the menu extension no longer tells Windows it can be unloaded while
>   File Explorer is still using it.
>
> ### Updating
>
> The Microsoft Store delivers this update automatically. If it reports that the update
> failed, restart File Explorer (or sign out and back in) and retry. Windows can't
> replace the menu extension while it's loaded.
>
> ### Still true
>
> No network calls, no telemetry, no account. Full policy in
> [PRIVACY.md](https://github.com/estevanhernandez-stack-ed/RTClickPng/blob/main/PRIVACY.md).
>
> **Install:** [Microsoft Store](https://apps.microsoft.com/detail/9PKKLK6R5WFL)
